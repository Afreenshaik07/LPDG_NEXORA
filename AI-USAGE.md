# 3. A Concrete Example of AI Being Wrong

An important example occurred during telemetry feature engineering.

An initial approach treated:

`offline_duration_sec`

as if it were an additive hourly quantity and summed it across the week.

That produced implausibly large weekly values.

The analysis exposed the problem because the resulting values were inconsistent
with the expected interpretation of a firmware-reported offline-duration
counter/state.

For example, the corrected analysis showed that the field had a very different
distribution when treated as the final observed weekly value rather than as a
weekly sum.

I investigated the field semantics and changed the aggregation rule:

- `offline_duration_sec` → final observed value in the week;
- `disconnection_cnt` → weekly sum;
- `reboot_cnt` → weekly sum;
- `reboot_duration_sec` → weekly sum.

This correction was made before using the corrected feature table for the final
Data Science evaluation and prediction pipeline.

This was an important example of why AI-generated suggestions were treated as
hypotheses that had to be tested against the actual data.

# 6. How AI Suggestions Were Evaluated

AI-generated suggestions were not accepted solely because they sounded
reasonable.

Each important methodological suggestion was evaluated against:

1. the supplied LPDG data;
2. the challenge requirements;
3. leakage and cutoff rules;
4. historical evidence;
5. operational cost implications;
6. reproducibility requirements.

Where an approach did not improve the evidence, it was not automatically added
to the final production system.

For example, feature ablation showed that some additional components did not
provide enough incremental value to justify replacing the existing production
ranking.

No external dataset was required for the final Data Science solution.

prediction pipeline.

# 8. AI and the Final Model Decision

The final model was selected from evidence generated by the participant's
experiments.

The participant compared:

- current-success-only ranking;
- success + deterioration;
- business-only combinations;
- the current production score;
- different future horizons;
- threshold settings;
- early-detection behaviour.

The final production score was retained because it provided strong short-term
operational performance while remaining competitive with simpler alternatives.

The final decision was therefore based on measured results rather than on an
AI recommendation alone.

---

# 9. Limitations of AI Assistance

Generative AI can:

- misunderstand the semantics of a data field;
- suggest a method that introduces leakage;
- produce code that does not match the actual file structure;
- overcomplicate a problem;
- make assumptions that are not supported by the supplied data.

For this reason, important AI-generated suggestions were tested locally before
being used.

The telemetry aggregation issue described above is one example where testing
was essential.
